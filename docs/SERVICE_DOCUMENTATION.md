## 1. Executive Summary

**clustron-backend** is the backend service of the **NYCU SDC Clustron** project
(`README.md`, `go.mod` module `clustron-backend`). Its core purpose, per the
README, is to *"visualize the LDAP access managing, Slurm operation, and resource
usage on remote computer cluster."*

Concretely, the service is a control plane that lets users and administrators
manage access to and workloads on an HPC-style compute cluster through a single
HTTP API. It ties together several external systems:

- **Users & authentication** — login via third-party OAuth (Google / NYCU /
  GitHub), issuing its own JWT access + refresh tokens.
- **LDAP** — provisions and manages POSIX user accounts and groups in OpenLDAP
  (the identity backend the cluster nodes authenticate against via SSSD).
- **Slurm** — creates Slurm accounts/associations and submits/queries jobs via
  the Slurm REST API (`slurmrestd`), so group membership in Clustron maps onto
  Slurm accounting.
- **Ansible** — provisions and configures cluster nodes ("servers"), rendering
  LDAP/NFS/NTP/Slurm roles onto machines.

It is written in **Go** (`go 1.26.2`) using the standard library `net/http`
router, `sqlc`-generated PostgreSQL access, Casbin for authorization, Redis for
caching, and OpenTelemetry for tracing. It is distributed as a Docker image
(`nycusdc/clustron-backend`).

Domain concepts:

- A **Group** (e.g. a course or lab) maps to two LDAP groups (a *BASE* group for
  regular members and an *ADMIN* group for owners/admins) and to a matching
  Slurm account hierarchy (`<cn>-base`, `<cn>-admin`).
- A **User** has a global role (`admin` / `organizer` / `user`) and, within each
  group, a group role with an access level (`GROUP_OWNER` / `GROUP_ADMIN` /
  `USER`).

## 2. Architecture

### 2.1 Package layout

The code follows a per-domain layered pattern under `internal/`. Each domain
package typically contains: `handler.go` (HTTP), `service.go` (business logic),
`queries.sql` + `queries.sql.go` (sqlc data access), `schema.sql` (that domain's
table definitions), `models.go`, `type.go`, `policy.csv` (Casbin rules), and
`mocks/` (generated test doubles).

```
clustron-backend/
├── cmd/backend/main.go        # composition root: config, DI wiring, router, server
├── internal/
│   ├── config/                # layered config (file -> env -> flags)
│   ├── casbin/                # RBAC enforcer, model.conf, merged full_policy.csv
│   ├── ldap/                  # OpenLDAP client (users, groups, reconnect logic)
│   ├── slurm/                 # Slurm REST API client + token helper + naming
│   ├── redis/                 # Redis cache service (slurm jobs/partitions)
│   ├── ansible/               # node provisioning; embeds ansible/ playbooks+roles
│   ├── auth/                  # OAuth login/bind, callback, internal login, role mw
│   │   └── oauthprovider/     # google.go, nycu.go, github.go providers
│   ├── jwt/                   # JWT issue/verify, refresh tokens, auth middleware
│   ├── user/                  # user CRUD, global roles; role/ subpkg
│   ├── setting/               # onboarding, LDAP bind, public keys, passwords
│   ├── group/                 # groups; ldapgroup/ subpkg for ldap_groups table
│   ├── grouprole/             # group roles + access levels
│   ├── membership/            # group membership + pending invites (saga-heavy)
│   ├── module/                # environment "modules" (JSONB env definitions)
│   ├── job/                   # Slurm job listing/submission/partitions (over slurm)
│   ├── system/                # first-admin "system setup" gate
│   ├── cors/  trace/          # middleware
│   ├── database/              # migrations/ + generated full_schema.sql
│   ├── saga.go                # generic Saga orchestrator (compensating steps)
│   ├── handler.go validator.go errors.go   # shared HTTP helpers
├── scripts/                   # create_full_schema.sh, create_full_policy.sh
├── test/                      # integration/, setup/, testdata/, testutil/
└── .deploy/                   # local/dev/stage/snapshot compose + ldif + slurm
```

Shared cross-cutting utilities come from the external module
`github.com/NYCU-SDC/summer` (`pkg/middleware`, `pkg/database`, `pkg/log`,
`pkg/problem`, `pkg/handler`, `pkg/config`) — see imports in `cmd/backend/main.go`.

### 2.2 Layering (per domain)

```
   HTTP request
       │
   ┌───▼──────────┐   parses/validates input, writes RFC-7807 problems
   │  Handler     │   (internal/<domain>/handler.go)
   └───┬──────────┘
       │ calls
   ┌───▼──────────┐   business logic; orchestrates DB + LDAP + Slurm
   │  Service     │   (internal/<domain>/service.go)
   └───┬──────────┘
       │ uses
   ┌───▼──────────┐   sqlc-generated Queries (internal/<domain>/queries.sql.go)
   │  Store/DB    │   over pgxpool  ──► PostgreSQL
   └──────────────┘
       │ (some services also hold)
       ├──► ldap.Client      (OpenLDAP)
       ├──► slurm.Service     (slurmrestd REST)
       └──► redis.Service     (cache)
```

Dependency injection is entirely manual in `cmd/backend/main.go`: queriers,
services, handlers, middleware, and the Casbin enforcer are all constructed and
wired there. Note the deliberate two-phase wiring for a dependency cycle:
`settingService.SetMembershipService(memberService)` is called *after*
`memberService` is built.

### 2.3 Router & middleware chains

The router is a plain `http.NewServeMux()` using Go 1.22+ method+path patterns
(e.g. `"GET /api/groups/{group_id}"`). Two middleware sets are built with
`summer/pkg/middleware`:

```
basicMiddleware = Recover ─► Trace
                  (used for public/unauthenticated endpoints)

authMiddleware  = Recover ─► Trace ─► EnsureSystemSetup ─► JWT ─► Role(Casbin)
                  (used for everything requiring a logged-in user)

CORS wraps the whole mux as the outermost layer (corsMiddleware.HandlerFunc).
```

- `Recover` / `Trace` — `internal/trace/middleware.go`
- `EnsureSystemSetup` — `internal/system/middleware.go`: returns HTTP 503
  `{"code":"system_not_setup"}` until a first admin exists (`HasAdmin`); caches
  the "setup done" state in an `atomic.Bool`.
- `JWT` — `internal/jwt/middleware.go`: reads `Authorization` header, parses the
  token, stashes the `User` in context.
- `Role` — `internal/auth/middleware.go`: extracts the user's **global role**
  and calls `enforcer.Enforce(role, path, method)` (Casbin).

## 3. Data Flows

### 3.1 OAuth login → JWT (source: `docs/flowcharts/OAuth.mermaid`, `internal/auth`)

```
Browser                     Backend                       OAuth Provider   DB
  │  GET /api/login/oauth/{provider}                          │            │
  │───────────────────────────►│ Oauth2Start                  │            │
  │                            │ validate provider,           │            │
  │                            │ build authz URL + state      │            │
  │◄───────────────────────────│ 302 redirect ───────────────►│            │
  │  user authenticates ......................................│            │
  │◄──── 302 back to /api/oauth/{provider}/callback?code ─────│            │
  │───────────────────────────►│ Callback                     │            │
  │                            │ exchange code ──────────────►│ token      │
  │                            │ fetch userinfo ─────────────►│ profile    │
  │                            │ find-or-create user ───────────────────►  │
  │                            │ issue JWT + refresh token ─────────────►  │
  │◄── 302 to frontend callback URL with token & refreshToken ─│            │
```

- Providers: `internal/auth/oauthprovider/{google,nycu,github}.go`.
- GitHub OAuth is used for **importing SSH public keys**, not primary login
  (`GET /api/publickey/import` → `authHandler.ImportGithubKeysHandler`).
- Token refresh: `GET /api/refreshToken/{refreshToken}` (`jwt` package).

### 3.2 Authenticated request

```
Request ─► CORS ─► Recover ─► Trace ─► EnsureSystemSetup ─► JWT parse
        ─► Casbin Enforce(globalRole, path, method)
        ─► Handler ─► Service ─► {Postgres | LDAP | Slurm | Redis}
        ─► JSON response (or RFC-7807 problem via summer/pkg/problem)
```

### 3.3 Group creation (cross-system, saga-orchestrated — `internal/group/service.go` `Create`)

Creating a group is a distributed transaction spanning Postgres, LDAP, and
Slurm, wrapped in the generic `internal.Saga` (`internal/saga.go`) which runs
compensating rollbacks in reverse order on failure:

```
Create group
  1. Postgres:  insert groups row, ldap_groups rows (BASE + ADMIN), membership
  2. LDAP:      create BASE group CN            (compensate: delete CN)
  3. LDAP:      create ADMIN group CN           (compensate: delete CN)
  4. Slurm:     create BASE account (top-level) (compensate: delete account)
  5. Slurm:     create <cn>-base + <cn>-admin child accounts under BASE
                                                (compensate: delete accounts)
     └─ any step fails ─► Saga compensates all executed steps in reverse
```

Slurm account naming: `internal/slurm/naming.go` — `BaseAccountName(cn)=<cn>-base`,
`AdminAccountName(cn)=<cn>-admin`. Group deletion (`Delete`) runs the inverse
saga (delete child accounts before parent, since slurmdbd refuses to delete an
account with child associations).

### 3.4 Adding a member (`internal/membership/service.go` `Add`/`Join`)

```
Add member to group
  1. Postgres:  insert membership (or pending_membership if user not yet onboarded)
  2. LDAP:      add user to ADMIN group CN (if admin/owner role)  [compensate: remove]
  3. LDAP:      add user to BASE group CN                          [compensate: remove]
  4. Slurm:     CreateUserAssociation(user, [accounts])           [compensate: DeleteAssociation]
```

If the invited identifier does not resolve to an existing onboarded user, the
invite is stored in `pending_memberships` and materialized later.

### 3.5 Slurm job/partition read path (`internal/slurm/service.go`, `internal/redis`)

```
GET /api/jobs ─► job.Service ─► slurm.Service.GetJobs(userID)
   ├─ Redis GET slurm jobs (cache hit ─► return)
   └─ miss ─► GetNewToken(userID) via token helper
            ─► GET {slurm_restful_base_url}/slurm/{ver}/jobs
               header X-SLURM-USER-TOKEN: <jwt>
            ─► cache into Redis ─► return
```

`GetNewToken` calls the **Slurm Token Helper**:
`GET {SLURM_TOKEN_HELPER_URL}/api/token/{ldapUsername}` with
`Authorization: Bearer {SLURM_TOKEN_HELPER_API_KEY}` (`internal/slurm/service.go`).

### 3.6 Node provisioning (`internal/ansible/service.go`)

Server rows are stored in Postgres (`servers` table). `SetupAll` /
`AddNode(s)` render an Ansible inventory and run embedded playbooks
(`internal/ansible/ansible/playbooks/nodes.yaml`, `update_roles.yaml`) via
`github.com/apenella/go-ansible/v2`, guarded by a mutex (`ansibleMu`) so runs
don't overlap. `allowed_login_groups` rows feed SSSD's `simple_allow_groups`.

## 4. API Routes

All routes are registered in `cmd/backend/main.go`. **Auth** column: `public` =
`basicMiddleware` (no JWT); otherwise the endpoint uses `authMiddleware`
(JWT + Casbin) and the listed value is the **global role** the Casbin policy
(`internal/casbin/full_policy.csv`) requires. Casbin role inheritance:
`admin ⊃ organizer ⊃ user` (an `admin` satisfies `user`/`organizer` rules).
Matching uses `keyMatch2` + `regexMatch` (`internal/casbin/model.conf`), so
`{param}` route segments match the `:param` policy patterns.

## 5. Database

- Engine: **PostgreSQL 18** (`.deploy/local/compose.yaml`, `README.md`).
- Access: **sqlc** (`sqlc.yaml`) generates `queries.sql.go` per package from each
  package's `queries.sql` plus a single merged schema
  `internal/database/full_schema.sql`. Driver: `pgx/v5` via `pgxpool`.
- Migrations: **golang-migrate** run automatically at startup
  (`databaseutil.MigrationUp` in `main.go`); 15 up/down pairs in
  `internal/database/migrations/`. `MIGRATION_SOURCE` points at them
  (`file://internal/database/migrations` locally, `file:///app/migrations` in
  Docker).
- `full_schema.sql` and `sqlc.yaml` are **generated** ("DO NOT EDIT") by
  `scripts/create_full_schema.sh`, which concatenates each domain's `schema.sql`.
  Migrations remain the source of truth for the live DB; `full_schema.sql` exists
  only to feed sqlc's type checking.

### 5.1 Tables (from `internal/database/full_schema.sql`)

| Table | Key columns | Notes / relationships |
|---|---|---|
| `users` | id (PK), email (unique), role (default `user`), full_name, student_id (unique) | Root identity. `role` is the global role string. |
| `login_info` | id (PK), user_id → users, providerType, identifier (unique), email | One row per linked OAuth account. |
| `login_tokens` | id (PK), user_id → users, callback, expires_at, is_active | Short-lived login/callback tokens. |
| `refresh_tokens` | id (PK), user_id → users, is_active, expiration_date | JWT refresh tokens. |
| `ldap_user` | id (PK, → users), uid_number (unique, from sequence) | 1:1 with users; POSIX uidNumber from `ldap_user_uid_number_seq` (starts at 10000). |
| `settings` | user_id (PK, → users), full_name, linux_username | Per-user settings/onboarding. |
| `public_keys` | id (PK), user_id → users, title, public_key | SSH public keys. |
| `groups` | id (PK), title, description, is_archived | A Clustron group (course/lab). |
| `ldap_groups` | id (PK), group_id → groups, ldap_cn (unique), type (`BASE`/`ADMIN`), gid_number (unique) | 1:2 with groups (a BASE and an ADMIN LDAP group); `UNIQUE(group_id, type)`. |
| `links` | id (PK), group_id → groups, title, url | Group-attached links. |
| `group_role` | id (PK), role_name, access_level (`GROUP_OWNER`/`GROUP_ADMIN`/`USER`) | Role definitions used by memberships. |
| `memberships` | user_id → users, group_id → groups, role_id → group_role; `UNIQUE(user_id, group_id)` | User's role within a group. |
| `pending_memberships` | id (PK), user_identifier, group_id → groups, role_id → group_role; `UNIQUE(user_identifier, group_id)` | Invites for users not yet onboarded. |
| `modules` | id (PK), user_id → users, title (unique), description, environment (JSONB) | Reusable environment definitions. |
| `servers` | id (PK), ansible_name (unique), ip_address / ssh_config_host, private_ip, ssh_user, ssh_key_name, ansible_role, slurm_partition, status (default `unset`), cpu_cores, memory_mb | Cluster nodes; rich CHECK constraints (hostname regex, connection XOR, positive cpu/mem). |
| `allowed_login_groups` | (server_id → servers, ldap_group_id → ldap_groups) PK | M:N; rendered into SSSD `simple_allow_groups`. |

FKs use `ON DELETE CASCADE` in many places (groups → ldap_groups/links/memberships/
pending; users → modules; servers/ldap_groups → allowed_login_groups). A canonical
ER diagram (for the user/group core) is maintained at `docs/ERDiagram.mermaid`.

## 6. External Dependencies

| Dependency | What / why | How it's accessed | Config keys |
|---|---|---|---|
| **PostgreSQL 18** | Primary data store | `pgx/v5` `pgxpool`; migrations via golang-migrate at boot | `DATABASE_URL`, `MIGRATION_SOURCE` |
| **OpenLDAP** | POSIX users/groups the cluster authenticates against | `github.com/go-ldap/ldap/v3` custom client `internal/ldap/client.go` (bind DN, reconnect+backoff, 5s dial / 10s request timeouts) | `LDAP_HOST`, `LDAP_PORT`, `LDAP_BASE_DN`, `LDAP_USER_OU_NAME`, `LDAP_GROUP_OU_NAME`, `LDAP_BIND_DN`, `LDAP_BIND_PWD`, `LDAP_DEBUG` |
| **Slurm REST API (`slurmrestd`)** | Account/user/association mgmt + job submit/query | HTTP client in `internal/slurm/service.go`; base `{SLURM_RESTFUL_BASE_URL}/slurm/{ver}` and `/slurmdb/{ver}`; auth header `X-SLURM-USER-TOKEN` | `SLURM_RESTFUL_BASE_URL`, `SLURM_RESTFUL_VERSION`, `SLURM_ROOT_TOKEN` |
| **Slurm Token Helper** | Mints per-user Slurm JWTs (tokens are only obtainable via CLI, so this sidecar exposes them) — repo: NYCU-SDC/slurm-token-helper | `GET {URL}/api/token/{ldapUsername}` with `Authorization: Bearer {API_KEY}` | `SLURM_TOKEN_HELPER_URL`, `SLURM_TOKEN_HELPER_API_KEY` |
| **Redis** | Cache for Slurm jobs / job-state / partitions | `github.com/redis/go-redis/v9` in `internal/redis/service.go` | `REDIS_URL` (optional) |
| **OAuth providers** | Login (Google, NYCU) + key import (GitHub) | `golang.org/x/oauth2` + providers in `internal/auth/oauthprovider/` | `GOOGLE_OAUTH_*`, `NYCU_OAUTH_*`, `GITHUB_OAUTH_*` |
| **Ansible** | Node provisioning (LDAP client/NFS/NTP/Slurm roles) | `github.com/apenella/go-ansible/v2` runs embedded playbooks in `internal/ansible/ansible/` | uses `LDAP` config + `servers` rows |
| **OpenTelemetry collector** | Distributed tracing export (OTLP/gRPC) | `otlptracegrpc`; no-op if unset | `OTEL_COLLECTOR_URL` (optional) |
| **OAuth proxy** (optional) | External proxy for OAuth redirect handling | `OAUTH_PROXY_BASE_URL` / `OAUTH_PROXY_SECRET` referenced in config; used to sign callback tokens | `OAUTH_PROXY_BASE_URL`, `OAUTH_PROXY_SECRET` |

Authorization itself is **in-process** via Casbin (`internal/casbin/`), not an
external service.

## 8. Common Gotchas

- **`make gen` is mandatory before build/test.** `build`, `test`, and `run` all
  depend on `gen`, which regenerates `full_schema.sql`, runs `sqlc generate`,
  regenerates `full_policy.csv`, and runs `mockery`. These generated files are
  marked "DO NOT EDIT" — hand-editing them is lost on the next `gen`. Editing a
  domain's `schema.sql`/`policy.csv`/`queries.sql` and forgetting to regenerate
  produces confusing stale behavior. Requires `sqlc` and `mockery` installed.
- **Schema lives in two places.** `internal/database/migrations/` is the runtime
  source of truth; `full_schema.sql` is only for sqlc. They can drift if a
  migration is added but the per-package `schema.sql` isn't updated.
- **Migrations run automatically at boot** (`MigrationUp` in `main.go`). A bad
  migration or a dirty migration state will `Fatal` the whole service on start.
- **Default JWT secret is rotated on every restart in non-debug mode.** If
  `SECRET == "default-secret"` and not in debug, `main.go` replaces it with a
  random UUID — meaning all previously issued tokens become invalid after a
  restart. Always set `SECRET` in production.
- **`config.yaml` is committed with real-looking dev credentials** (OAuth client
  secrets, a Slurm root JWT, LDAP bind password `password`, and `preset_user`
  admin emails). This is a local dev file; do not treat it as safe/authoritative,
  and do not reuse those secrets. Production values come from env/injected
  secrets (see the CI `inject_secret` blocks).
- **Config precedence & godotenv Overload.** Order is file → env → flags, and
  `godotenv.Overload()` *overrides* already-set environment variables from a
  `.env` file. A stray `.env` can silently shadow real env vars.
- **System is locked until a first admin exists.** `EnsureSystemSetupMiddleware`
  returns HTTP 503 `system_not_setup` for most endpoints until `HasAdmin` is
  true. Bootstrapping relies on `preset_user` (base64 `PRESET_USER` env or the
  `preset_user` config block) granting `admin`, plus onboarding. The "is set up"
  result is cached in an `atomic.Bool` for the process lifetime.
- **Slurm and LDAP must be reachable or many endpoints fail.** `make run` warns
  if the local Slurm cluster isn't listening on `:6820` ("Group creation and job
  endpoints will fail"). LDAP requires the `ou=People` and `ou=Groups` OUs to
  pre-exist (see README LDAP initialization); the app validates the LDAP
  connection at boot and `Fatal`s if it can't connect.
- **Slurm tokens are indirect.** The backend cannot mint Slurm JWTs itself; it
  depends on the external **slurm-token-helper**. Without it configured, all
  `/api/jobs*` and `/api/partitions` calls fail.
- **Sagas are best-effort, not transactional across systems.** Compensation
  failures are only *logged* (`internal/saga.go`), so a partial failure can leave
  Postgres/LDAP/Slurm inconsistent if a rollback step also fails. There is no
  automatic retry/reconciliation.
- **Casbin authorization only checks the global role.** The role middleware
  enforces on `user.Role` (global), not per-group access level. Group-scoped
  authorization (owner/admin/member) is enforced inside the services, not by
  Casbin — so reading only `full_policy.csv` under-describes real access rules.
- **Policy vs route param-name mismatches** exist (see §4 note). They work due to
  `keyMatch2` but are easy to misread.
- **Go version divergence.** `go.mod` declares `go 1.26.2` and the Dockerfile uses
  `golang:1.26.2`, but the README's local-dev instructions mention Go 1.24. Use
  the `go.mod` / Dockerfile version to be safe.
- **The `bin/backend` binary is committed** and is what the Dockerfile copies —
  the image is not built from source inside Docker; CI builds the Linux binary
  first (`GOOSlinux go build ...`) then builds the image.

## 9. Common Operations

All commands are from the repo root. Source: `Makefile`, `.github/workflows/`,
`README.md`, `.deploy/local/`.

### Build / run locally

```bash
make run        # download deps, start local depend-services (postgres, ldap, redis)
                # via .deploy/local/compose.yaml, run `make gen`, build, and run
                # the backend with DEBUG=true
make build      # runs `make gen` then builds bin/backend
make gen        # regenerate full_schema.sql, sqlc code, full_policy.csv, mocks
make clear      # docker compose down -v the local services and rm bin/
```

`make run` requires Docker (for Postgres/LDAP/Redis) and, for group/job features,
a local Slurm cluster (see below). Local backend port comes from `config.yaml`
(`port: 8082`) unless overridden.

### Local dependent services

```bash
# Postgres 18, OpenLDAP, Redis (+ optional phpLDAPadmin on :6443)
docker compose -f ./.deploy/local/compose.yaml up -d --wait
docker compose -f ./.deploy/local/compose.yaml down -v --remove-orphans
```

### Local Slurm cluster (for group/job endpoints)

```bash
make slurm-up     # ./.deploy/local/slurm/deploy.sh — dockerized slurmctld/slurmdbd/slurmrestd
make slurm-token  # mint a root JWT to paste into config.yaml slurm.slurm_root_token
make slurm-down   # tear down
```

Then copy the `slurm:` block from `.deploy/local/slurm/config.slurm-local.yaml`
into `config.yaml` and paste the token. slurmrestd is exposed on host `:6820`.
See `.deploy/local/slurm/README.md` for details.

### Test

```bash
make test         # go test -cover ./...   (runs `make gen` first)
```

Integration tests under `test/integration/` use `github.com/ory/dockertest/v4`
to spin up real Postgres/LDAP containers (`test/setup/`, `test/testutil/`), so
Docker must be available. Mocks are generated by `mockery` (`.mockery.yaml`).

### Lint

```bash
golangci-lint run     # also runs automatically as a pre-push hook (lefthook.yml)
```

### Debug

- Run with `DEBUG=true` (or `-debug`) for development logging (`initLogger` uses
  `summer` Zap dev config) and to keep the default secret stable across restarts.
- `ENABLE_INTERNAL_LOGIN=true` exposes `POST /api/internal/login` for password
  login without OAuth (dev only — `main.go` warns to disable in production).
- `GET /api/setup/status` reports whether the system has been initialized.
- `LDAP_DEBUG=true` enables verbose LDAP logging.
- OpenTelemetry traces (spans named per service, e.g. `slurm/service`,
  `auth/middleware`) export to `OTEL_COLLECTOR_URL` when set.
- `make flow-chart` (needs `go-callvis`) renders a call graph of `cmd/backend`.

### CI / Deploy

- `.github/workflows/pull-request.yml` and `main.yml`: **Lint → Test → Build →
  Deploy**. Build compiles a Linux binary, then builds & pushes the Docker image
  to `nycusdc/clustron-backend` (`:dev` and `:<sha>` on `main`; `:pr-<n>` on PRs).
- Deploy triggers an **n8n webhook** (`https://webhook.sdc.nycu.club/webhook/deploy`)
  that injects secrets (Infisical-style paths) and sets up the environment
  (`dev` for main, `snapshot` for PRs). There is no direct `kubectl`/SSH deploy in
  the repo.
- Docker image entrypoint: `/app/backend`, expects migrations at `/app/migrations`
  and Casbin `model.conf`/`policy.csv` at `/app/` (see `Dockerfile`,
  `MIGRATION_SOURCE=file:///app/migrations`). Published images: Docker Hub
  `nycusdc/clustron-backend` (`stage` = stable, `dev` = development).
